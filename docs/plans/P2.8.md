## Context

The P2 gate passed on 2026-11-12. The phase review that followed (PROGRESS.md, Open
questions, "P2 phase review, bypass audit") found six gaps in what the policy checks
(N1–N6) and three more items. None is reachable today: there are no real handlers. Each
becomes reachable the moment a P3 handler exists, so all are fixed before P3. P3 cannot
start until P2.8 is done and reviewed by Karthik. This plan also absorbs P3.0a and P3.0b.

Trust model used throughout: the model is untrusted; core code is trusted (it is our code and
the model has no tool that changes it). Fixes take decisions away from the model. They do
not assume the core is hostile.

Preference: fail closed, enforced in `safety/` or the bridge, never per handler.

Accepted, with reason — budgets reset with a new task: the budgets (8 calls, 120 s,
3 failures) bound one request's loop. The model cannot open a task; the core opens one per
user request. P3.5 gets a test that the core opens exactly one task per request.

Not unregistering OpenJarvis built-ins: the registry has no remove, and clearing upstream
internals is fragile and gives false assurance. The SDK passes no tools when none are named
(`OpenJarvis/src/openjarvis/sdk.py`, `tools or []`), so the risk is a call site naming a
built-in. That is what the tests in F guard.

## Design

### A. Path rules — `safety/policy.py`, `bridge/app.py` (undo only)

`resolve_inside(raw, roots, protected, mutating=False)`:

1. Drive check BEFORE `os.path.realpath` (P3.0a): refuse a path whose drive letter matches
   no root's drive. A path on a mapped network drive never makes Windows contact the share,
   and the policy lock is never held across a network lookup.
2. When `mutating` is true (after the existing roots and protected checks):
   - refuse a path that IS a root ("the root itself") — N1;
   - refuse a path that CONTAINS a protected folder ("contains a protected folder") — N2.

`Policy._check` and `_recheck` pass `mutating = rule.tier >= Tier.T1`. For each name
parameter, the landing place `parent(first path parameter) / name` must also pass
`resolve_inside(..., mutating=True)`; it is returned in `Decision.paths` as `target` so the
handler never builds it. `recheck` re-validates it like any other path. The undo route's
`resolve` passes `mutating=True`.

T0 tools are unchanged: `list_dir` on the root, or on a folder that contains a protected
folder, still works (it lists names only).

### B. Argument rules — `safety/policy.py`

`Rule` gains the complete list of allowed argument names: path parameters, name
parameters, plus `choice_params` (value must be a key of a named allowlist) and
`text_params` (one string, length-capped, no control characters). Any argument name the
rule does not declare is refused; a required argument that is missing is refused. A tool
with no declared arguments accepts none.

`Policy.__init__` gains `apps` and `scripts` (sets of names). The bridge loads them from
`config/apps.toml` and `config/scripts.toml` at start; a missing file means an empty set,
so every `open_app` / `run_named_script` call is refused until Karthik adds entries
(P3.2, P3.3). Only Karthik edits those files. The handler later receives the validated
name only; mapping a name to a command stays in the config file, never in a model argument.

`test_tool_table_matches_eval_stubs` is extended: the eval stubs' parameter names must
equal the rules' declared names, so the two cannot drift.

### C. Taint — `safety/policy.py`, `bridge/app.py`

- `list_dir`, `list_windows` and `recall_memory` get `taints=True` (file names, window
  titles and stored text are attacker-shaped).
- The bridge keeps one conversation-level taint flag. `Policy.record` reports taint as
  today; when a task becomes tainted the bridge sets the flag. `POST /task` creates the
  new task already tainted while the flag is set.
- `POST /task` accepts `{"fresh_context": true}` (core role only): the core declares it has
  dropped the model's conversation context. The flag clears and the new task starts clean.
  Logged in the `task` audit line. The ui token cannot clear taint (it cannot call `/task`).
- A bridge restart clears the flag (pending actions are gone too; the core must start a new
  conversation after a restart — recorded as a P3.5 requirement).
- ponytail: one flag, one conversation at a time. Per-conversation ids if Jarvis ever runs
  two conversations.

Known consequence: with `list_dir` tainting, "sort the downloads folder" needs a click per
move. P3.2 designs one batch confirmation for a multi-file move on a tainted task. Until
then each move is confirmed singly (strict, not broken).

### D. Stop latch — `bridge/app.py`

`stop(source)` sets `halted = True` when the source is `hotkey` or `ui`. While halted,
`POST /task` and `POST /tool` answer 403 `stopped` (logged). `POST /resume` (ui only,
logged, new `ROUTE_ROLES` entry and route-table test entry) clears it. A stop relayed by
the core stops current tasks only, as today (a spoken "stop" must not need a UI visit).
`stop()` still takes no lock and never depends on the audit log. Until P6 has a button,
resume means restarting the bridge or calling `/resume` with the ui token by hand.

### E. Kill-switch liveness and audit encoding — `bridge/hotkey.py`, `bridge/app.py`, `safety/audit.py`

- `Listener.alive()` returns whether the hotkey thread is running. Before any handler runs
  (`execute`), if a hotkey is configured and the listener is not alive: `stop("hotkey-dead")`,
  latch, answer 503 `kill switch unavailable`. Same rule as at startup: no kill switch, no
  tools. `hotkey=None` (tests only) skips the check.
- `AuditLog` opens the file with `errors="backslashreplace"`, so a lone surrogate in an
  argument or a result is written escaped instead of raising after the handler ran.

### F. Tests only

- Built-in tools guard (`tests/test_core_tools.py`): every `tools=` list passed in `core/`
  and `evals/` is a subset of `safety.policy.TOOLS` (plus the eval stubs' names, which
  must equal `TOOLS`, and the throwaway `hello_bridge`); an executor built from that list
  refuses `shell_exec`, `file_write`, `http_request`, `apply_patch`; the configured default
  agent is one that brings no tools of its own.
- Token sweep: two `x-jarvis-token` headers (one valid, one wrong) and two `Host` headers
  are refused on every route (P3.0b); wrong-role case for every route (nit c).
- Path sweep: missing parameter and non-string value over HTTP (nit d).

## Limits to record

- The conversation taint flag trusts the core's `fresh_context` claim. A core bug that
  sends it without dropping context defeats the taint. P3.5 must test that.
- The latch covers `/task` and `/tool`. An approve already past its checks is covered by
  the existing stopped-checks, not by the latch.
- Allowlists are read at start; editing `apps.toml` or `scripts.toml` needs a bridge restart.
- The drive check compares drive letters, not volumes: a `subst` or mapped letter that
  matches a root's letter is still resolved by `realpath` as before.
