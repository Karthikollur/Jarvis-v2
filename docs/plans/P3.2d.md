# P3.2d — `focus_window` lands through minimise + restore; attach removed

Planner: Claude Code (Fable 5.1), 2026-11-14. Status: APPROVED by Karthik 2026-11-14
(option "minimise+restore, drop attach"). Not implemented. Implementer: Cursor.

## Context

Two manual checks through a running bridge on 2026-11-14, after P3.2c, audit log read back:

- Notepad covered by another window: FAIL. `OSError` 518 ms after `allow`. 518 ms is both
  250 ms waits timing out: the plain `SetForegroundWindow` did not land, the attach to the
  foreground thread ran, the attached call did not land either. A genuine refusal.
- Notepad minimised: PASS. `{"focused": true}` 228 ms after `allow`. `focus_window` calls
  `ShowWindow(SW_RESTORE)` first when the window is iconic; the restore itself brought
  Notepad to the front, past the lock.

Windows 11 keeps the foreground lock against a long-running background process. The
`AttachThreadInput` route (P3.2b) has never been seen working through the bridge. Restoring
a minimised window has. The 228 ms is close to the 250 ms cap: the WinUI Notepad restore
animation takes most of it.

Probes run from this planning session were discarded as evidence: a fresh child process of
the foreground window inherits the right to set the foreground, so such probes succeed for
reasons the bridge never has. Only results through the bridge count.

Outcome wanted: "focus notepad" through a running bridge answers `focused: True` and Notepad
is in front, covered or minimised. When even the restore does not land, the tool still fails
honestly.

## Design (`bridge/tools.py`)

`_to_front(hwnd)` becomes:

```
_to_front(hwnd) -> bool
  1. SetForegroundWindow(hwnd); if _settled(hwnd): return True
  2. ShowWindow(hwnd, SW_MINIMIZE); ShowWindow(hwnd, SW_RESTORE)
  3. return _settled(hwnd)
```

- `SW_MINIMIZE = 6` next to `SW_RESTORE = 9`.
- `_settled` keeps its shape; its default `timeout` becomes `0.5` (the restore took ~200 ms
  through the bridge; 250 ms leaves no margin). Comment: `# ponytail: 500 ms cap; make it
  config if a slow app needs more`.
- `focus_window` is unchanged: the `IsIconic -> ShowWindow(SW_RESTORE)` step before
  `_to_front` stays (a minimised window needs no minimise step; the restore alone lands
  it, as the manual check showed), the `OSError` text stays, `{"focused": True}` stays.
- The ponytail comment on the refusal line changes to: if the restore does not land, the UI
  (P6, a foreground process) can grant `AllowSetForegroundWindow` to the bridge.
- **Removed**: `AttachThreadInput`, `GetWindowThreadProcessId` use in `_to_front`,
  `IsHungAppWindow`, the own-thread and no-foreground guards, `import threading`, and the
  `argtypes`/`restype` lines that only they used. `GetWindowThreadProcessId` keeps its
  declaration from `_all_windows`. Dead code goes; a route never seen working is not kept
  as a fallback.

Why minimise + restore is acceptable: `ShowWindow` needs no foreground right, touches only
the target window, and the pair leaves a maximised window maximised (Windows restores the
pre-minimise state). Cost: one visible flicker when the plain call is refused. No key
presses, no `SystemParametersInfo`, no global input state.

## Tests (`tests/test_tools.py`, tests first, red run shown)

`FakeUser32` gains `lands_on_restore: bool` (default False): when `ShowWindow(hwnd,
SW_RESTORE)` is called and this is set, `foreground` becomes `hwnd` (subject to
`settles_after` hiding, as today). The `show` call stays in the log as `("show", hwnd,
command)`.

Removed with the attach code: `AttachThreadInput`, `GetWindowThreadProcessId`,
`IsHungAppWindow`, `threads`, `hung`, `attached`, `attach_refuses`, `raise_when_attached`,
`needs_attach`, the `covered()` helper, `OTHER_THREAD`, and the nine P3.2b tests plus
P3.2c's tests 2, 3 and 5 (they assert the attach log). Keep and adapt: P3.2c tests 1 and 4,
the five original P3.2 `focus_window` tests, and `refused_by_windows_fails` (now: refused,
restore does not land).

New tests:

1. Plain call refused, restore lands: `{"focused": True}`; log is exactly
   `("foreground", 104), ("show", 104, SW_MINIMIZE), ("show", 104, SW_RESTORE)`.
2. Plain call refused, restore lands after 2 reads (`settles_after`): `{"focused": True}`.
3. Plain call refused, restore does not land: `OSError("refused")`; log shows both `show`
   calls; the fake clock's total sleep is at most `2 * 0.5 + 0.01`.
4. Plain call accepted: no `show` call at all (no flicker on the happy path).
5. Minimised window, plain call refused after the first restore, second restore lands:
   log is `("show", 104, SW_RESTORE), ("foreground", 104), ("show", 104, SW_MINIMIZE),
   ("show", 104, SW_RESTORE)`.
6. Grep guard: `AttachThreadInput` and `IsHungAppWindow` no longer appear in
   `bridge/tools.py` (one assertion reading the source file; keeps the dead route from
   coming back unplanned).

`FakeClock` cap becomes `2 * 0.5 + 0.01`.
