## Rules every handler follows (Karthik, 2026-11-13)

1. Paths come only from the policy. A handler reads `args["path"]`, which the bridge has
   already replaced with the realpath-resolved, root-checked `Decision.paths` value
   (`execute`: `handler({**args, **paths})`). A handler never joins, normalises, expands or
   re-resolves a path, and never calls `realpath`.
2. Never follow a link. `list_dir` reports a symlink or junction as `"type": "link"` and
   never looks inside it. `read_text_file` refuses a path that is a reparse point, and
   after opening checks that the open handle's final path equals the checked path
   (`GetFinalPathNameByHandleW` via ctypes), so a swap to a link between the policy check
   and the open is refused, not followed.
3. Results are plain JSON data only: dict with str keys, list, str, int, float, bool, None.
   A shared test helper `assert_plain(value)` walks the result and fails on anything else
   (tuple, Path, bytes, datetime, set, non-str key); every handler test uses it.
4. A handler that cannot do its job raises; the bridge already logs `failed` and answers
   500 "Tool failed" without the error text (P2.4). No partial results dressed as success.
5. No dependency. stdlib + ctypes only (see system_stats for the one question).

## Commits

**A. `P3.1: list_dir`** (also adds `bridge/tools.py`, the `create_app` default, and
`assert_plain`)

- `os.scandir(path)`; per entry `{"name", "type"}` with type `file` / `dir` / `link` /
  `other`, and `"size"` for files. `link` = `entry.is_symlink() or entry.is_junction()`,
  checked first; `is_dir` / `is_file` are called with `follow_symlinks=False`.
- Sorted: folders first, then by name (case-insensitive), so results are stable.
- Cap: 200 entries, result `{"entries": [...], "total": n, "truncated": bool}`.
- A path that is not a folder raises (bridge answers failed).
- Tests: files, folders, a junction inside the root (reported as `link`, its target's
  contents never listed), sorted order, cap at 201 entries, empty folder, a file path
  fails, plain-data check, a name with a lone surrogate still answers 200 (P2.9 C
  encoding). Taint: through `/tool`, `list_dir` then `create_folder` on the same task is
  queued (202), not run.

**B. `P3.1: read_text_file`**

- Cap: 16 KiB (16384 bytes). Read at most cap + 1 bytes; over the cap returns the first
  16 KiB with `"truncated": true`. Result `{"text", "bytes", "truncated"}` where `bytes` is
  the file size from the open handle.
- Text check: a NUL byte in what was read means binary: raises. Decode UTF-8 (BOM
  stripped) with `errors="replace"`, so any byte sequence gives a str.
- Link rule (rule 2): `os.lstat` refuses a reparse point (`st_file_attributes &
  FILE_ATTRIBUTE_REPARSE_POINT`); open with `os.open(path, O_RDONLY | O_BINARY)`; then
  `GetFinalPathNameByHandleW` on `msvcrt.get_osfhandle(fd)` must equal `path`
  (case-insensitive, `\\?\` prefix stripped), else raise. A folder path raises.
- Tests: small file, exact cap, cap + 1 (truncated), empty file, UTF-8 with BOM, invalid
  UTF-8 (replacement chars, still plain), NUL byte refused, folder refused, symlink file
  refused if this account can create one (else skipped, like the existing symlink test),
  final-path mismatch refused (the swap is simulated by patching the final-path helper),
  plain-data check. Taint: `read_text_file` then `create_folder` is queued.

**C. `P3.1: list_windows`**

- ctypes: `EnumWindows`; keep windows that are visible, have a non-empty title and no
  owner (`GetWindow(GW_OWNER) == 0`), i.e. what the taskbar shows. Per window
  `{"title", "pid", "app"}`, where `app` is the process image's file name
  (`OpenProcess(PROCESS_QUERY_LIMITED_INFORMATION)` + `QueryFullProcessImageNameW`, only
  the base name; `null` if access is denied, e.g. an elevated process).
- Cap: 50 windows, titles cut to 200 characters (`MAX_TEXT`), so a web page cannot flood
  the context. Result `{"windows": [...], "truncated": bool}`.
- No window handles in the result: P3.2 `focus_window` takes a title, as its policy rule
  already says.
- Tests: on this desktop it returns a list (may be empty in CI-like sessions: allowed);
  the shape and plain-data check; with `EnumWindows` replaced by a fake that yields fixed
  titles, the filter, the 200-character cut and the 50 cap are exact. Taint:
  `list_windows` then `create_folder` is queued.

**D. `P3.1: system_stats`**

- CPU %: `GetSystemTimes` sampled twice, 200 ms apart (blocks the call 0.2 s).
- RAM: `GlobalMemoryStatusEx`: `ram_used_gb`, `ram_total_gb`, `ram_percent`.
- GPU and VRAM: see the question below. Default proposal: `nvidia-smi` (present at
  `C:\Windows\System32\nvidia-smi.exe`; this laptop has an RTX 3050 6 GB and Intel UHD)
  run as one fixed argument list, no shell, 2 s timeout:
  `--query-gpu=name,utilization.gpu,memory.used,memory.total --format=csv,noheader,nounits`.
  If it is missing, fails or times out, `"gpu": null` and the rest still answers.
- Result `{"cpu_percent", "ram_used_gb", "ram_total_gb", "ram_percent", "gpu": {"name",
  "percent", "vram_used_gb", "vram_total_gb"} | null}`, numbers rounded to 1 decimal.
- Not tainting (numbers only; the GPU name is a fixed vendor string), as the policy says.
- Tests: real call returns the shape, values in range, plain-data check; `nvidia-smi`
  output parsing on a fixed string; missing executable, timeout and junk output each give
  `"gpu": null`, not a failure.
