## Context

P3.5 manual check (2026-11-16) passed the core, bridge and policy, but the P3 "Done when"
("Open VS Code on my sandbox project and sort the downloads folder by file type") failed on
model behaviour. Three tries, each one tool call or none, then a text answer:

- The model never chains `list_dir` -> `create_folder` -> `move_files`. It reads "sort" as
  "show grouped". Prompt rule 6 in `core/config.toml` ("After a tool result, reply in one
  short sentence") ends the turn after the first result. Rule 5 ("Never invent a path")
  discourages creating `pdf\`.
- t25 ("Open VS Code on my sandbox project.") expects `C:\JarvisSandbox`. With real tools
  the model called `list_dir` first (taints the task), then chose `...\project`.
- `evals/run.py:144` counts the fast path by the stub reply string, so `--real` prints 0/42.
- `--real --model X` ignores `--model` but prints it in the summary.

Why the stub evals could not see this: every stub returns `"<name>: done (stub, nothing
really happened)"` (`evals/stub_tools.py:33`), so `list_dir` shows no files and a second
step can never be chosen. And `score()` (`evals/run.py:38`) judges `calls[0]` only.

Outcome wanted: a repeatable stub eval case that fails today and passes after a prompt
change, then the P3 "Done when" through the real core and bridge.

as a JSON string. Every other stub is unchanged. Two file types on purpose (see Manual check).

`evals/run.py`:
- `score()`: optional case key `also` (list of tool names). A tool case passes only if every
  name in `also` appears among `calls[1:]` (set membership, order not checked: the SDK may
  run calls in parallel). The returned dict keeps its three keys; `also` folds into `passed`.
- Fast-path count: each row carries a `fast` bool. Stub branch: `bool(routed)`. Real branch:
  `not opts.no_router and route(case["say"]) is not None` (`core.router.route`, the same
  function `build()` defaults to). The summary sums that bool. The row label prints
  `fast`/`llm ` in both branches.
- `--real` with `--model`: `parser.error("--model has no effect with --real")`.

`evals/commands.yaml`:
- t25 `say` becomes `"Open VS Code on my sandbox folder."`; expected args unchanged.
- New t26: `say: 'Sort C:\JarvisSandbox\downloads by file type'`, `expect: tool`,
  `tool: list_dir`, `args: {path: 'C:\JarvisSandbox\downloads'}`,
  `also: [create_folder, move_files]`. Header comment: 43 cases, `also` explained.

Tests:

## Section B — prompt (commit `P3.5b: multi-step prompt`)

`core/config.toml`, rules 5 and 6 only. Starting text:

- 5: `Never invent a path, file name, app or script the user did not mention. The one
  exception: a new folder you create to carry out the request, named after what goes in it.`
- 6: `A request can need several tool calls. To sort a folder by file type: list it, create
  one folder per file type inside it, then move each group in with move_files. Keep calling
  tools until the whole request is done, then reply in one short sentence suitable for
  speaking aloud.`

Loop: edit, run `uv run python evals/run.py`, read t26 and the summary. At most 5 variants;
record each variant's text and score in the Session log. Accept when, on two runs in a row:
t26 ok, refusals 10/10, clarify 5/5, and no case fails that passed in Section A's runs.

If no variant passes in 5: stop, no commit, report the replies. The next step is Karthik's
decision (bigger model, or a composite sort tool with its own policy entry), not Cursor's.

No test change: `tests/test_core.py` reads the prompt from the file (`PROMPT`, line 179).
