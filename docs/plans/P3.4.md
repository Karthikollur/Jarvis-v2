## Context

PLAN.md P3.4: "Prefer CLIs and app APIs (e.g. `code <path>`) over UI clicking; pywinauto only
where needed." The P3 "Done when" ("Open VS Code on my sandbox project and sort the test
downloads folder by file type") needs one thing that does not exist yet: opening an app **on
a path**. `open_app` takes only the name. The sorting half is covered by `list_dir`,
`create_folder` and `move_files`.

Karthik's decisions (2026-11-15):
- New T1 tool `open_in_app(app, path)`. No optional-argument feature in the policy.
- `apps.toml` entries declare `accepts = "file" | "folder" | "any"`: vscode any, explorer
  folder, notepad file, calculator none (refuses `open_in_app`).
- One new eval case t25; the count goes 41 -> 42, as for `move_files`.
- pywinauto: a decision and a plan rule (rule 11), no code.

Two facts that shape the design:
- `Policy._resolve` treats every path of a T1/T2 tool as one it may change, so the root
  itself is refused ("the root itself"). Opening VS Code on `C:\JarvisSandbox` IS the root.
  The policy needs one flag: a path that is only handed to an app is not changed.
- On this Python a junction is a directory to `lstat` (`S_ISDIR` True, `S_ISLNK` False) with
  `st_reparse_tag = 0xA0000003` (checked 2026-11-15). "Never follow a link" for a folder
  means checking `st_reparse_tag`, not `S_ISLNK`.

## Rules (inherit `docs/plans/P3.2.md` 1-7 and `docs/plans/P3.3.md` 8-10), plus

11. CLI or app API first. A tool drives an app through its command line or a documented API
    (`Code.exe <path>`, `explorer.exe <folder>`). UI automation (pywinauto, key presses,
    clicks) needs its own plan that names the app, what was tried through its CLI/API, and
    why that is not enough. No pywinauto dependency until then.
12. `Rule.opens=True` is only for a tool that hands a path to another program and changes
    nothing itself. Such a path may be the root; it is still refused outside the roots and
    inside a protected folder, and the handler never follows a link or junction.

`bridge/tools.py`:
- `@dataclass(frozen=True) class App: command: list[str]; accepts: str | None` (mirror of
  `Script`).
- `load_commands` becomes `load_apps(config) -> dict[str, App]`: same fail-closed rules via
  `_checked_command`; allowed keys `command`, `accepts`; `accepts` one of `"file"`,
  `"folder"`, `"any"`, else `ValueError`; unknown key `ValueError` (as `load_scripts`);
  missing file -> `{}`. Call sites: `bridge/app.py` (`create_app`) and the tests.
  `mutating(undo_log, apps, scripts=None)`; `open_app` reads `apps[name].command`.
- New handler in `mutating`:

```python
def open_in_app(args):
    name, path = args["app"], args["path"]        # both checked by the policy (rule 1)
    app = apps[name]
    if app.accepts is None:
        raise OSError(f"{name} does not open a path")
    found = os.lstat(path)                         # never follow a link or junction (rule 12)
    if found.st_reparse_tag or not (stat.S_ISREG(found.st_mode) or stat.S_ISDIR(found.st_mode)):
        raise OSError("not a plain file or folder")
    kind = "file" if stat.S_ISREG(found.st_mode) else "folder"
    if app.accepts not in (kind, "any"):
        raise OSError(f"{name} opens a {app.accepts}, not a {kind}")
    process = subprocess.Popen(
        [*app.command, str(path)], shell=False,
        stdin=subprocess.DEVNULL, stdout=subprocess.DEVNULL, stderr=subprocess.DEVNULL,
    )
    return {"opened": name, "pid": process.pid}
```

- The path is one argv item after the fixed command. A policy-resolved path starts with a
  drive letter, so it can never be read as an option. No undo record (like `open_app`).
- `# ponytail:` an app that takes no path fails in the handler (500 `Tool failed`, one
  failure counted), not in the policy: a third allowlist is not worth a `Policy` kwarg for a
  refusal that is not a security boundary (the policy already bounds `app` and `path`).
