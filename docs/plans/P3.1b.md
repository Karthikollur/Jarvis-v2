## G2 and the P3.2 handlers (confirmed 2026-11-13)

The G2 fix covers P3.2 as follows. A hard link is dangerous only to a handler that opens
a file's CONTENT: the content is shared with the other name, which may be outside the
roots. A handler that only changes a NAME (`os.rename`) touches that one name; the other
name and the content stay where they are.

| Handler (P3.2 plan) | Opens file content? | Hard link effect | Covered by |
|---|---|---|---|
| `create_folder` | no (`os.mkdir`) | none: folders cannot be hard-linked | nothing needed |
| `rename_file`, `move_file`, `move_files` | no (`os.rename` via `_move`) | only the name inside the root moves | nothing needed; P3.2 rule 3's `os.lstat` does not see a hard link and need not |
| `open_app`, `focus_window` | no file argument | none | nothing needed |
| undo / quarantine (`safety/undo.py`) | no (`os.rename`) | only the name moves | nothing needed |
| `read_text_file` (P3.1) | YES | reads the outside file | commit B |

So no P3.2 handler has the gap, and commit B makes that a standing rule instead of an
accident: the check lives in one helper, `_single_name(fd)` in `bridge/tools.py`, and the
module docstring's rules gain "a handler that opens a file's content calls
`_single_name` on the open handle". Commit B also adds that sentence as rule 7 to
`docs/plans/P3.2.md` ("Rules for every handler"). Limit, stated plainly: nothing
enforces the rule mechanically; a future content-reading or content-writing handler
(none is planned in P3.2 or P3.3) must call the helper and bring its own hard-link test.

  ```python
  def _single_name(fd: int) -> os.stat_result:
      """Refuse a file with a second name (hard link): that name may live outside the
      roots, and realpath cannot see it. Every handler that opens content calls this."""
      stat = os.fstat(fd)
      if stat.st_nlink != 1:
          raise OSError("file has more than one hard link")
      return stat
  ```
