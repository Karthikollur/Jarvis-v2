## Not in this plan: closing the static built-in tools guard (P3.5)

`tests/test_core_tools.py` scans `tools=` keyword arguments in `core/` and `evals/`. It
misses positional arguments, other keyword names, a direct `ToolExecutor([...])`, files
elsewhere, and `_build_tools` silently dropping unknown names. Proposal for P3.5:
1. One core module builds the tool list from `safety.policy.TOOLS`; the AST test then
   checks that nothing else calls `ask` / `ask_full` / `ToolExecutor`.
2. At core start, assert the executor's real tool names equal `TOOLS` and the agent adds
   none; otherwise refuse to start.
3. A scripted fake engine calls every name in `ToolRegistry` through that entry point;
   anything not in `TOOLS` must answer "Unknown tool" and reach no handler.
4. Each core tool's `execute` only POSTs to the bridge's `/tool`.
