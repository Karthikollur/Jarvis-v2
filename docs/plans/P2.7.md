## Design

### 1. Policy lock — `safety/policy.py`

- `Policy.__init__` gains `self._lock = threading.Lock()`. `check`, `recheck` and `record`
  run their whole body under it (rename the current bodies or wrap with `with self._lock:`;
  `_stop` and `out_of_time` stay lock-free helpers, the lock is not re-entrant).
- One lock for all tasks: `# ponytail: global lock, per-task locks if throughput matters`.
  It is held across `os.path.realpath` (a few file-system calls), never across a handler.
- The bridge is unchanged: `stop()` never calls `Policy`, so Stop never waits on this lock.
  `task.stopped = True` stays a plain attribute write.
- No new dependency (`threading` is stdlib, same pattern as `AuditLog` and `ConfirmQueue`).

### 2. Stop racing a queued action — `bridge/app.py`, `/tool` only

After `queue.add` succeeds and before the `queued` audit line: if `task.stopped`, take the
action back out (`queue.take`), set its outcome to `cancelled`, log `queued` with
`refused="task stopped"`, answer 403 `task stopped`. About six lines, next to the existing
"unlogged action must not be approvable" branch. `stop()` itself is not touched and takes no
lock (it must never wait on anything). The remaining window (Stop landing after this check)
is covered as before: approve's `recheck` refuses a stopped task, `execute` refuses again
right before the handler.

### 3. Tests only

- Fix line 249 to a real device path and add real UNC forms over HTTP.
- Two sweeps driven by the live tables, so P3 additions are covered automatically:
  every route in `app.routes`, every tool in `safety.policy.TOOLS` with `path_params`.

Tests (deterministic, no sleeps-and-hope):
- Call budget: a test-only `Task` subclass whose read of `calls` waits at a
  `threading.Barrier` (short timeout). Task at 7 calls, N threads call `check`. Without the
  lock all N meet at the barrier and all are allowed; with it exactly one is allowed, the
  rest get `call budget exceeded`, `task.calls == 8`.

## Limits to record

- The lock makes each policy decision atomic; it does not order a decision against Stop.
  That is handled by the three stopped-checks (after queueing, at recheck, before the handler).
- Stop landing after `execute`'s last check does not interrupt the handler (existing limit).
- One global lock: all policy checks are serial. Fine for one user and 8 calls per task.
