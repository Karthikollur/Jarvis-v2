## Section A — `delete_file` (commit `P3.3: delete_file`)

Status: Implemented 2026-11-15.

`bridge/tools.py`, inside `mutating(undo_log, commands)`:

```
def delete_file(args):
    path = args["path"]                            # resolved by the policy (rule 1)
    if not stat.S_ISREG(os.lstat(path).st_mode):   # lstat: never follow a link
        raise OSError("not a plain file")          # files only in v1 (rule 3)
    record = undo_log.quarantine(path, "delete_file")
    return {"deleted": True, "undo_id": record.id}
```

- Result shape matches `create_folder` / `move_file`.
- Nothing is ever unlinked. `quarantine` moves with `os.rename` (refuses cross-drive), then
  writes the record. Known limit (already in the P2.6 list): if the record write fails after
  the move, the item sits in `quarantine/<id>/item` without a record.
- Add `delete_file` to the dict `mutating` returns.

`bridge`, `fresh_task`, `call`, `ui`):

   bytes, `undo_log.get(undo_id).kind == "quarantined"`, result shape exact.
2. A folder: `OSError("not a plain file")`, folder still there, no record written.
3. A junction (and a symlink, skipped where the account cannot create one) in the root

## Section C — `run_named_script` (commit `P3.3: run_named_script`)

Status: Implemented 2026-11-15. `_tail` and `OUTPUT_TAIL` live at module level in
`bridge/tools.py` (they close over nothing). The handler is inside `mutating`.

`bridge/tools.py`, inside `mutating`:

```
OUTPUT_TAIL = 4096  # characters of combined output returned to the model

def run_named_script(args):
    name = args["name"]                       # on the allowlist: the policy checked
    script = scripts[name]
    try:
        done = subprocess.run(
            script.command, shell=False, cwd=script.cwd, timeout=script.timeout,
            stdin=subprocess.DEVNULL, stdout=subprocess.PIPE, stderr=subprocess.STDOUT,
        )
    except subprocess.TimeoutExpired as expired:
        return {"ran": name, "timed_out": True, "exit_code": None,
                "output": _tail(expired.output or b"")}
    return {"ran": name, "timed_out": False, "exit_code": done.returncode,
            "output": _tail(done.stdout)}

def _tail(raw: bytes) -> str:
    return raw.decode("utf-8", errors="replace")[-OUTPUT_TAIL:]
```

- No undo record (like `open_app`). The audit line carries the result.
- `# ponytail:` on the timeout: `subprocess.run` kills the direct child only; children of a
  `.cmd` can outlive it. Upgrade path: a Job Object when a real script needs it.
- `# ponytail:` on blocking: the handler blocks the worker up to `timeout`; Stop does not
  interrupt a running handler (known P2.6 limit). The 60 s cap keeps it under the 120 s task
  budget.
- Output goes back to the model; that is why the tool taints (section B).

Tests (`tests/test_tools.py`, a fake `subprocess.run` via monkeypatch like `fake_popen`,
plus one real run through the bridge):

1. Fixed argv: `run` gets exactly the entry's `command`, `shell=False`, `stdin=DEVNULL`,
   `cwd` and `timeout` from the entry; result shape exact.
2. Output tail: 10 000 characters of output -> `output` is the last 4096.
3. Timeout: fake raises `TimeoutExpired(output=b"partial")` -> `timed_out True`,
   `exit_code None`, `output "partial"`; no exception out of the handler.
4. Non-zero exit: `exit_code 3`, no exception (not a tool failure).
5. Bytes that are not UTF-8: decoded with replacement, no exception.
6. Through the bridge, real run: fresh task, `run_named_script name=run_tests` -> 202;

8. Through the bridge: `/deny` -> `run` never called; `/outcome` `denied`.
