## Context

PLAN.md 4.2: "Kill switch. Global hotkey (default `Ctrl+Alt+End`, configurable) and a tray/UI
Stop button cancel the running task and clear the confirm queue." Today nothing can stop a
task except its own budgets. `ConfirmQueue.clear()` exists but nothing calls it, and it drops
pending actions without an outcome (so `/outcome` would answer 404). `core/router.py` already
returns `("stop", {})` with no tool behind it.

Outcome: one `stop()` in the bridge, reachable two ways — `POST /stop` and a global hotkey —
that stops every live task, cancels every pending action, and logs it.

Karthik's answers (2026-11-11):
1. After Stop, new tasks are accepted at once. No halted state, no resume route.
2. If the hotkey cannot be registered, the bridge refuses to start.
3. `/stop` is open to both roles, `core` and `ui`.
4. If the audit write fails while stopping: stop anyway, answer 200 with `logged: false`.

## Design

**`stop(source)`** — one inner function in `create_app` (`bridge/app.py`), the only stop path:
1. `task.stopped = True` for every task in `list(tasks.values())` (count the ones newly stopped).
2. `dropped = queue.clear()`; each gets `outcomes[id] = {"status": "cancelled"}`.
3. `log("stop", source=..., tasks=<count>, cancelled=[pending ids])`.
4. Returns `{"stopped": n, "cancelled": m, "logged": bool}`.

Stopping happens BEFORE the audit write. This is the one deliberate exception to P2.4's
write-before-run rule: stopping is the safe direction and must never depend on the log.

**Changes around it**
- `safety/confirm.py`: `clear()` returns the dropped `Pending` list (was `None`).
- `bridge/app.py`:
  - `ROUTE_ROLES["/stop"] = {"core", "ui"}`; `POST /stop` calls `stop(<role>)`.
    `Authenticate` puts the resolved role in `scope["state"]["role"]` so the route can log it.
  - `unknown_pending()`: 410 for `cancelled` as well as `expired`.
  - `execute()` refuses a stopped task right before the handler call (403 `task stopped`,
    outcome and `result` line `cancelled`). Closes the window where an approve already past
    `recheck` would still run after Stop.
  - `/outcome` gains status `cancelled`.
- Existing behaviour reused, unchanged: `Policy.check` and `Policy.recheck` already refuse a
  stopped task (`safety/policy.py`), so every later `/tool` and `/approve` for it is refused.

**Hotkey** — `bridge/hotkey.py` (new, stdlib `ctypes` only, no dependency):
- `parse("Ctrl+Alt+End") -> (modifiers, vk)`. At least one modifier required. Keys: A–Z, 0–9,
  F1–F24, End, Home, Pause, Insert, Delete, Esc. Anything else raises `ValueError`.
- `listen(combo, callback) -> Listener`: a daemon thread calls `RegisterHotKey` (with
  `MOD_NOREPEAT`), then loops on `GetMessageW`; `WM_HOTKEY` -> `callback()`. `listen` waits
  for the thread to report and raises `RuntimeError` if registration failed.
  `Listener.close()` posts `WM_QUIT` and unregisters.
- `config/hotkey.toml` (new): `stop = "Ctrl+Alt+End"`. Only Karthik edits it.
- `create_app(..., hotkey=<default: read config/hotkey.toml>)`. A FastAPI lifespan starts the
  listener with `callback = lambda: stop("hotkey")` and closes it on shutdown. Default ON, so
  the production command in AGENTS.md is unchanged and cannot run without a kill switch.
  `hotkey=None` turns it off (tests only). A failed registration fails startup.
- `tests/conftest.py`: autouse fixture replaces `bridge.hotkey.listen` with a fake, so the
  suite never grabs a real global hotkey. The hotkey's own tests use the real function.

**Limits, to record in Decisions**
- A handler that is already running is not interrupted; Stop prevents everything after it.
  P3 handlers must be short or killable (matters for `run_named_script`; P6 wants "within 1 s").
- `Policy`/`Task` still have no lock (P2.7). A `/tool` call racing Stop can queue an action
  on a stopped task; approve's `recheck` refuses it.
- Any same-user process can press the hotkey or call `/stop`. That only stops things.
