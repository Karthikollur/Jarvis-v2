## Rules for every handler (as P3.1, plus)

1. Paths only from the policy: `args["path"]`, `args["source"]`, `args["target"]` are the
   resolved `Decision.paths`. A handler never builds, joins or re-resolves a path.
   `rename_file` and `move_file` move to `target` and ignore `new_name` / `destination`.
2. Never delete, never overwrite. Every move is `os.rename`, which on Windows refuses an
   existing target and a cross-drive move. A refusal means nothing moved.
3. Files only in v1: `rename_file` / `move_file` refuse a folder and a link
   (`os.lstat`, no follow). Smaller blast radius; the stubs say "file".
4. Act, then record. If the undo record cannot be written, a move is renamed back and the
   call fails. A folder that was created but could not be recorded is left (never deleted)
   and the call fails; the audit line says failed.
5. Results are plain data (`assert_plain`) and carry no untrusted text: `focus_window`
   does NOT return the window title (the tool does not taint, so it must not leak one).
6. No dependency: stdlib + ctypes. No pywinauto in P3.2.
7. A handler that opens a file's content calls `_single_name` on the open handle (refuses
   a hard link; P3.1b G2). None of A to F opens content; a future one brings its own
   hard-link test.
