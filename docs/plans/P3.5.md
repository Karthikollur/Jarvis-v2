## Context

PLAN.md P3.5: "Register tools in core; rerun evals against real tools in the sandbox. The core
opens exactly one task per user request and sends `fresh_context` only when it has dropped
the model's context (also after a bridge restart); tests for both. Runtime tools guard: one
`BridgeTool` class in `core/`; before every request the agent's real tool set must equal
`TOOLS` by name and be exactly `BridgeTool` by type, else refuse. Tests include the refused
case."

Today the model only ever meets stub tools (`evals/stub_tools.py`) and the bridge is driven by
hand (`Jtool` in PowerShell). Nothing connects `core/` to `bridge/`. The P3 "Done when"
sentence needs that connection.

Karthik's decisions (2026-11-15):
- The core builds `OrchestratorAgent` itself (engine, model, `tools=[BridgeTool...]`,
  `parallel_tools=False`, `system_prompt` from `core/config.toml`). Not `ask_full`:
  `_build_tools` (`OpenJarvis/src/openjarvis/cli/ask.py:304`) silently drops unknown names,
  runs tool calls in parallel (the bridge answers 409 to a second call on one task), and never
  returns the agent, so the guard could not see the real tool set. `ToolRegistry` is not used
  for bridge tools.
- `fresh_context` is the caller's statement: `Core.handle(text, fresh=True)`. `fresh` resets the
  conversation and sends `{"fresh_context": true}`; `fresh=False` keeps the previous exchange
  and sends no flag. The CLI is always fresh. A bridge restart changes nothing in the core: a
  bridge that starts tainted stays tainted until the next fresh request (fail-closed; the
  model's context is not affected by a bridge restart). No `/health` change.
- `evals/run.py --real` runs every case through the real core and a running bridge. T2 cases
  wait for Karthik's approve/deny in tab 2 (or the 120 s task budget). The default run keeps
  the stubs.
- HTTP client: stdlib `urllib`. No new dependency. Tests start the real bridge with uvicorn in
  a thread on a free loopback port.

Facts that shape the design (checked 2026-11-15):
- `bridge/tools.py` `HANDLERS` has no `get_time` and no `recall_memory`: both answer 501
  `Tool not implemented`. `get_time` is added in section C (T0, no arguments, trivial).
  `recall_memory` stays 501 until P4; the core maps 501 to a failed tool result.
- `ToolExecutor.execute` (`OpenJarvis/src/openjarvis/tools/_stubs.py:435`) cuts a tool at
  `spec.timeout_seconds` (default 30 s) and leaks the worker thread. A tool that waits for an
  approval must declare `timeout_seconds` above the bridge's `MAX_SECONDS`.
- Bridge answers: 200 `{"result": ...}`; 202 `{"pending_id": ...}`; `/outcome` returns
  `{"status": "pending" | "done" | "failed" | "denied" | "expired" | "cancelled", "result"?}`;
  403 / 404 / 409 / 410 / 500 / 501 / 503 carry `{"detail": ...}`.
- `_build_messages` (`agents/_stubs.py:201`) prepends `context.conversation.messages`; the
  agent does not append to it. The core appends the user text and the final answer itself
  when it carries history (tool calls in between are not carried).
- `OllamaEngine(host)` (`openjarvis/engine/ollama.py:118`) is a public constructor with no
  side effects. The SDK's `_ensure_engine` wraps it in security and telemetry layers the core
  does not need (the bridge is the policy; telemetry is off). `load_config(path)` from
  `openjarvis.core.config` reads `core/config.toml`.
- The system prompt and tool schemas the model sees are unchanged from the stub evals, so
  `--real` measures the same tool choice plus the real result round-trip.

## Rules (inherit `docs/plans/P3.2.md` 1-7, `P3.3.md` 8-10, `P3.4.md` 11-12), plus

13. The core never decides permission. Every tool call, fast path included, goes to the
    bridge as a request. A refusal, a denial or a bridge error is an observation for the
    model, never retried by code, and never answered with a built-in tool.
14. The runtime guard runs before every request on the agent's own tool objects: names equal
    `TOOLS`, every object is exactly `BridgeTool` (`type(t) is BridgeTool`). A mismatch
    refuses the request before the model or the bridge is called.
15. One `POST /task` per user request, opened after the guard and the router, before the
    first tool call. Tool calls inside one request share that task.

`core/bridge_client.py`:

```python
BASE = "http://127.0.0.1:8765"
TOKEN = Path(os.environ["LOCALAPPDATA"]) / "Jarvis" / "bridge.token"  # read only; the bridge makes it

class BridgeError(RuntimeError):
    """A bridge answer the core cannot continue from (no task id)."""

class BridgeClient:
    def __init__(self, base: str = BASE, token: str | None = None):
        if not base.startswith("http://127.0.0.1:"):
            raise ValueError("bridge must be loopback")           # localhost only, rule 13
        token = TOKEN.read_text(encoding="ascii") if token is None else token
        if not re.fullmatch(r"[0-9a-f]{64}", token):
            raise RuntimeError("Invalid bridge token")
        self._base, self._headers = base.rstrip("/"), {"x-jarvis-token": token, "content-type": "application/json"}

    # No proxies: urlopen would honour HTTP_PROXY and could send a loopback call off the box.
    _opener = urllib.request.build_opener(urllib.request.ProxyHandler({}))

    def _post(self, path: str, body: dict) -> tuple[int, Any]:
        request = urllib.request.Request(self._base + path, data=json.dumps(body).encode(), headers=self._headers, method="POST")
        try:
            with self._opener.open(request, timeout=MAX_SECONDS) as response:
                return response.status, json.loads(response.read() or b"{}")
        except urllib.error.HTTPError as error:
            return error.code, json.loads(error.read() or b"{}")

    def new_task(self, fresh: bool) -> str:
        status, body = self._post("/task", {"fresh_context": True} if fresh else {})
        if status != 200:
            raise BridgeError(f"{status}: {body.get('detail', '')}")
        return body["task_id"]

    def tool(self, task_id, name, args) -> tuple[int, Any]: return self._post("/tool", {"task_id": task_id, "tool": name, "args": args})
    def outcome(self, pending_id) -> tuple[int, Any]: return self._post("/outcome", {"pending_id": pending_id})
    def stop(self) -> tuple[int, Any]: return self._post("/stop", {})
```

`MAX_SECONDS` is imported from `safety.policy` (the bridge's own wall budget: a tool never
runs longer). A connection error (`URLError`, bridge down) propagates: the caller says the
bridge is not running. No retries.

## Section B — `core/tools.py` + `core/agent.py` (commit `P3.5: core agent`)

`core/tools.py`:

```python
POLL = 0.5  # seconds between /outcome reads while an action waits for a click

class BridgeTool(BaseTool):
    """One bridge tool. The bridge and safety/ decide; this only carries the call (rule 13)."""

    def __init__(self, name, client, task: Callable[[], str], on_pending=None, clock=time.monotonic, sleep=time.sleep):
        self.tool_id = name
        ...

    @property
    def spec(self) -> ToolSpec:
        description, parameters = SPECS[self.tool_id]
        return ToolSpec(name=self.tool_id, description=description, parameters=parameters,
                        timeout_seconds=MAX_SECONDS + 10)   # the executor must not cut an approval wait

    def execute(self, **params) -> ToolResult:
        status, body = self._client.tool(self._task(), self.tool_id, params)
        if status == 202:
            status, body = self._wait(body["pending_id"])
            if status != 200:  # a bridge error while waiting
                return ToolResult(self.tool_id, f"bridge {status}: {body.get('detail', '')}", False)
            if body["status"] != "done":
                return ToolResult(self.tool_id, body["status"], False)     # denied / expired / cancelled / failed
            return ToolResult(self.tool_id, json.dumps(body["result"]), True)
        if status == 200:
            return ToolResult(self.tool_id, json.dumps(body["result"]), True)
        if status == 403:
            return ToolResult(self.tool_id, f"refused: {body.get('detail', '')}", False)
        return ToolResult(self.tool_id, f"bridge {status}: {body.get('detail', '')}", False)

    def _wait(self, pending_id):
        if self._on_pending: self._on_pending(pending_id)
        deadline = self._clock() + MAX_SECONDS
        while True:
            status, body = self._client.outcome(pending_id)
            if status != 200 or body.get("status") != "pending" or self._clock() >= deadline:
                return (status, body) if status != 200 or body.get("status") != "pending" else (200, {"status": "timed out"})
            self._sleep(POLL)

def bridge_tools(client, task, on_pending=None) -> list[BridgeTool]:
    return [BridgeTool(name, client, task, on_pending) for name in TOOLS]
```

`execute` never raises for a bridge answer (any status code). A connection error or a
non-JSON body (bridge down or crashed) does raise from the client: on the agent path
`ToolExecutor.execute` (`OpenJarvis/src/openjarvis/tools/_stubs.py`) catches it and the
model sees `Tool execution error: ...`; on the fast path it reaches the caller (section C's
CLI says the bridge is not running). No extra handling in `BridgeTool`. The result content is the bridge's ASCII-escaped JSON as a string:
the model reads it as an observation. `on_pending(pending_id)` is the one hook the eval runner
(and P6's UI) needs to tell Karthik an action waits; `None` by default.

`core/agent.py`:

```python
class GuardError(RuntimeError):
    """The agent's tool set is not the bridge's: nothing runs."""

class Core:
    def __init__(self, client, engine, model, system_prompt, *, temperature, max_tokens, router=route, on_pending=None):
        self._task_id = None
        self._tools = bridge_tools(client, lambda: self._task_id, on_pending)
        self._agent = OrchestratorAgent(engine, model, tools=self._tools, parallel_tools=False,
                                        system_prompt=system_prompt, temperature=temperature,
                                        max_tokens=max_tokens, max_turns=MAX_CALLS + 1,
                                        before_tool_call=self._record)
        self._context = AgentContext()
        self.calls: list[tuple[str, dict]] = []   # every tool call the model made, for evals --real

    def handle(self, text: str, fresh: bool = True) -> str:
        self._guard()                                # rule 14, before anything
        routed = self._router(text) if self._router else None
        if routed == ("stop", {}):
            self._client.stop()                      # a spoken stop: ends tasks, no latch
            return "Stopped."
        if fresh:
            self._context = AgentContext()
        self._task_id = self._client.new_task(fresh)  # rule 15: one task per request
        if routed:
            name, args = routed
            self._record(name, args)
            result = self._tool(name).execute(**args)
            return result.content if result.success else f"Could not {name}: {result.content}"
        answer = self._agent.run(text, self._context).content
        self._context.conversation.add(Message(role=Role.USER, content=text))
        self._context.conversation.add(Message(role=Role.ASSISTANT, content=answer))
        return answer

    def _guard(self):
        held = list(self._agent._tools)              # the agent's own list (upstream pinned at e6b7137)
        if {t.spec.name for t in held} != set(TOOLS) or any(type(t) is not BridgeTool for t in held):
            raise GuardError("agent tool set is not the bridge tool table")

    def _record(self, name, args) -> bool:          # OrchestratorAgent.before_tool_call hook
        self.calls.append((name, args)); return True

def build(config_path=REPO / "core" / "config.toml", on_pending=None) -> Core:
    import core.openjarvis_env  # noqa: F401
    config = load_config(str(config_path))
    engine = OllamaEngine(host=config.engine.ollama.host)
    return Core(BridgeClient(), engine, config.intelligence.default_model, config.agent.default_system_prompt,
                temperature=config.intelligence.temperature, max_tokens=config.intelligence.max_tokens, on_pending=on_pending)
```
